# F-005 — Login timing enumeration remediation

Date: 2026-08-31

Baseline: `75338bcd2d4ca6b53f146626bce66b9923714506`

Status: **FIXED**

## Implementation

- Added a fixed production-format scrypt dummy hash in `src/lib/referee-security.ts`.
- The dummy uses the same 16-byte salt representation and 64-byte derived-key length as `hashPassword()` but was generated from random discarded material and is unrelated to any real account, production secret, or known login password.
- Added strict usable-hash recognition. Missing, malformed, wrong-algorithm, wrong-salt-size, and wrong-key-size values are treated as unusable.
- `authenticateAdminCredentials()` and `authenticateRefereeCredentials()` now execute exactly one verifier call for every queried identity class:
  - eligible account + usable hash: verify against the real hash;
  - nonexistent, inactive, missing hash, or unusable hash: verify against the dummy hash.
- Legacy admin password verification also uses the dummy hash when its configured hash is absent/unusable.
- The blank-username legacy path remains single-KDF by selecting legacy authentication before account authentication; generic response and legacy behavior remain unchanged.
- No fixed sleep was added. The remediation performs equivalent scrypt work.

Rate-limit key construction, five-failure threshold, 15-minute block, failure delay, HTTP status, and generic error messages were not changed.

## Bounded runtime regression

Environment: Node `v22.23.2`, production `next start`, localhost, disposable SQLite and identities, no proxy or production traffic.

- 6 identities per class.
- 2 attempts per identity.
- 12 samples per class for admin active/nonexistent and referee active/nonexistent.
- 48 measured requests plus 4 warm-ups, versus 168 measured requests in R2 verification.
- Requests randomized/interleaved inside each failure ordinal.
- Gate: absolute identity-median difference below 25 ms and no complete class separation.
