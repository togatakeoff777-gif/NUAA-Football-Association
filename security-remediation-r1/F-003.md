## 实现方式

- 公开 POST 使用可信代理合约提供的 `X-Real-IP` 派生专用哈希 rate-limit key；完全忽略客户端可变的 `X-Forwarded-For`。
- 使用现有 `LoginAttempt` 表实现持久化 fixed-window quota，无 schema/migration 变更。
- 专用记录的 `blockedUntil` 表示首次成功提交后的固定窗口结束时间；窗口内累计、到期归零，不因后续请求刷新窗口。
- 校园 NAT/shared IP 策略为每真实地址 15 分钟最多 30 个成功创建，不是“一 IP 一申请”。
- 达到阈值返回 typed `429`，事务在申请行创建前终止。
- 姓名进行 NFKC、trim 与空白折叠；学号进行 NFKC 与大写规范化；手机号/QQ 继续使用原纯数字校验。
- 学号相同，或规范化姓名与手机号/QQ 组合相同，且存在 7 天内 `PENDING` 申请时返回 typed `409`；不同姓名共用联系方式不会被误判为同一 identity。
- 当前单 Node 进程拓扑下，按学号、姓名+手机号、姓名+QQ 三组实际去重标识联合加锁，配合数据库事务消除同进程并发重复；若未来改为多进程/多实例，需要另行授权 schema 级 idempotency/unique 设计。

## 新增测试

`scripts/test-security-admission-worker.ts` 使用隔离 SQLite 数据库覆盖：

- 轮换伪造 XFF 不改变可信地址 key。
- 首次申请创建 `PENDING`。
- 规范化身份重复提交返回 409，申请表增加 0 行。
- 同一共享地址的多个不同申请人可成功创建。
- 同学号但不同姓名/联系方式的两个并发请求严格得到一次成功、一次 typed 409，业务表仅 1 行。
- 预置达到阈值后返回 429，申请表增加 0 行。
- 固定窗口到期后计数归 1，并建立新的精确 15 分钟窗口。
