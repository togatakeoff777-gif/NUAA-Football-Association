## 实现方式

- 新增统一 server-side `authorizeRefereeMemberBusinessRequest()`。
- mutation 依次验证 Origin、member session、`session.referee.mustChangePassword`，之后才允许 route 读取 body/params 或调用业务 service。
- required-password 状态统一返回 `403` 和 canonical code `MEMBER_PASSWORD_CHANGE_REQUIRED`。
- 唯一保留窄路径：login、logout、password change；当前 API inventory 不需要额外 bootstrap endpoint。

## Regression tests

production-mode 真实 HTTP 覆盖：

- profile PATCH
- availability POST/DELETE
- applications POST/DELETE
- appointment acknowledge POST
- appointment conflict POST

全部在 `mustChangePassword=true` 时返回 canonical 403。测试在登录后、全部 blocked request 前后比较 referee profile、availability、applications、acknowledgements、conflicts，业务快照完全一致。dummy resource IDs 仍返回 403 而非下游 404，证明 guard 位于业务读取之前。

另验证：

- password change 进入既有 typed 401，而不是 required-password 403。
- logout 返回 200。
- 清除测试 fixture 的 required flag 后，profile 正常 200，合法业务流未被永久阻断。
